# Concept Learner · 概念学习资料生成器

## 适用场景

- 用户提出"帮我学习/搞懂/理解一下 XXX 概念"，对象是**单一概念**。
- 用户要求为某概念生成"学习笔记 / 学习资料 / 概念卡片"。
- 本仓库内需要为新概念补充学习资料（如课程布置新的学习主题）。

定位：把陌生概念转化为**结构完整、来源可核查、语言个人化**的学习资料。它面向真实学习者，产出"人能读懂、能复述、能自测"的笔记。纯 AI 腔的百科堆砌、整段照搬官方定义，均属于失败输出。

## 输入信息

执行前确认以下信息（缺省时给出合理默认并说明）：

| 输入项 | 说明 | 示例 |
|---|---|---|
| 概念名称 | 必填，要学习的概念 | `RAG` |
| 概念的英文/别名 | 可选，便于检索来源 | `Retrieval-Augmented Generation` |
| 领域上下文 | 可选，帮助定位（默认 AI/大模型方向） | 人工智能 |
| 输出文件 slug | 可选，默认概念名称的连字符小写形式 | `rag` |
| 输出目录 | 可选，默认 `learning-materials/` | `learning-materials/` |

## 生成步骤

按顺序执行，**每步不可跳过**：

1. **澄清与命名**：确认概念名称与领域。有歧义时（一词多义）先和用户确认方向，再定 slug。
2. **来源规划**：先想清楚权威资料在哪，优先级：官方文档/论文原文 > 机构技术博客 > 知名教材/维基 > 高质量二手解读。禁止凭空编造来源。
3. **检索与核对**：
   - 每个概念至少 **3 组关键词**（中文 1-2 组 + 英文 1-2 组），覆盖"定义与机制""论文或官方文档""误区与最佳实践"三个角度，优先用 `query_keyword_groups` 一次完成。
   - 对关键官方来源用 WebFetch 深入提取。
   - **每条要引用的链接逐一打开核实**，确认存在且内容支撑对应论断。
   - 重要论断至少 2 个独立来源一致才可写为"确定事实"；无法验证的标"待核实"。
4. **按模板写作**：按下方"输出结构"（八小节）逐节撰写；套用 `references/template.md` 骨架。
5. **个人化加工**：为概念补"我自己的类比/理解"，说明它像自己已知的什么。这是本 Skill 的特色要求。
6. **自检**：对照"自检清单"逐条检查，不通过则回头修改。
7. **落盘**：写入 `<输出目录>/<slug>.md`；目录不存在则创建。文件顶部必须带元信息块（见输出结构）。完成后告知用户文件路径、关键结论与不确定项，并建议用户亲自通读核查。

## 输出结构

文件须包含以下部分，**同时文件顶部先写元信息块**：

```markdown
---
concept: <概念名>
english_alias: <英文/别名>
domain: <领域>
generated_by: concept-learner
date: <YYYY-MM-DD>
review_status: 待人工核查
---
```

1. **学习目标**：学完能回答的 2-3 个问题。
2. **一句话理解**：≤3 句话的个人化解释，禁止整段照抄定义；附一个生活化类比。
3. **核心机制 / 组成**：内部怎么运作，配 Mermaid 图或分步列表，禁止只给定义不讲过程。
4. **具体应用场景**：1-2 个真实场景（说明输入、输出、为什么用它）。
5. **容易混淆的概念辨析**：≥2 个易混概念，表格对比 + 区分口诀。
6. **使用边界 / 常见误区**：何时不该用它、易犯的错误，澄清一个大众误解。
7. **自测问题**：3-5 题（判断/简答/场景题），答案折叠在 `<details>` 标签中。
8. **参考来源**：≥3 个真实链接，每条注明"支撑文中哪个论断、是什么资料"。

## 资料来源要求

- 官方文档、学术论文、标准原文优先；引用前必须用检索工具确认链接有效。作业明确规定"资料来源不得伪造"。
- 每条来源标注用途（支撑哪个论断）；不确定、找不到出处的说法删除或标注"待考证"。
- 每份资料至少 3 个独立可核查来源。

## 自检清单（落盘前逐条过）

- [ ] 元信息块齐全（concept/date/generated_by/review_status）
- [ ] 八个小节全部存在、顺序符合模板
- [ ] "一句话理解"是自己的话，无整段照搬
- [ ] 核心机制讲清"内部怎么工作"，而非只有定义
- [ ] 有 ≥1 个真实具体应用场景
- [ ] 概念辨析表区分 ≥2 个易混概念
- [ ] 每条参考来源均已核实、可点击
- [ ] 全文无「不是……而是……」句式，无 AI 腔（"首先/其次/最后"连发、空泛排比）
- [ ] 无敏感信息（密钥、隐私）混入
- [ ] 已在回复中建议用户亲自核查
